## 一、简历重点说明什么（换口径）

之前那份 ClearChain 文档是按"嵌入式开发"写的。投网络中心，要把它改讲成"**我懂网络**"的故事：

### 1. 把项目的"网络部分"提到最前面
不要写"我做了个 RFID 终端"，要写"我做的设备**如何联网、如何通信、如何排障**"：

- **无线接入**：设备作为 WiFi STA 完整实现「扫描 → 按 SSID 筛选 AP → 关联认证 → DHCP 动态获取 IP → 校验连通」全流程，含失败重试与超时机制。
- **SoftAP 模式（加分点）**：能让设备反向变成一个无线热点，配置静态 IP（192.168.63.1/24）、子网掩码、网关，并**运行 DHCP 服务器**给下挂设备分配地址，打印接入/离开设备的 MAC 地址。
- **TCP/IP 编程**：在 lwIP 协议栈上用原生 socket 实现 TCP 客户端，手写 HTTP/1.1 POST 报文（含 Host 头、Content-Length），用 DNS（gethostbyname）解析域名。
- **内网穿透**：通过 ngrok 让内网设备被公网访问（对应校园网里的端口映射/DMZ 概念）。
- **排障素养**：代码里全是"自检 probe、重试循环、超时保护、分级日志"——这正对应故障检修的思路，面试可以举例。

### 2. 简历建议条目（可直接改用）
> 基于 WS63 + LiteOS 开发物联网终端：实现 WiFi STA 扫描/关联/DHCP 获取 IP 全流程，
> 支持 SoftAP 热点模式并配置 DHCP 服务器与静态网段（192.168.63.0/24）；
> 在 lwIP 上以原生 socket 实现 TCP/HTTP 通信与 DNS 解析；
> 具备分层排障习惯（自检、重试、超时、日志定位）。

### 3. 面试一句话定位
"我不只是会配电脑，我做过从无线关联到 DHCP 取地址、再到 TCP 应用层的完整链路，

## 三、重点了解什么知识点（笔试 + 面试）

### 1. 网络基础（必考）
- **OSI 七层 / TCP-IP 四层**模型，每层一个设备/协议例子（物理层-网线，链路层-交换机/MAC，网络层-路由器/IP，传输层-TCP/UDP，应用层-HTTP/DNS）。
- **IP / 子网掩码 / 网关**：会算 192.168.1.0/24 有多少可用主机（254）、会判断两台设备是否同网段、知道私有网段（10/8、172.16/12、192.168/16）。
- **常见协议和端口**：DHCP 67/68（UDP）、DNS 53、HTTP 80、HTTPS 443、SSH 22。
- **ARP 与 MAC 地址**：为什么有了 IP 还要 MAC；`arp -a` 看什么。
- **DHCP 四步**：Discover → Offer → Request → ACK（你的代码里就是客户端这一侧，能讲出来很加分）。

### 2. 交换机与无线 AP（岗位直接相关）
- **交换机 vs 路由器 vs AP** 的区别（二层转发 vs 三层路由 vs 无线接入）。
- **VLAN** 概念：隔离广播域；Access 口 vs Trunk 口。
- **WiFi 基础**：2.4G vs 5G 区别；2.4GHz 三个不重叠信道 **1/6/11**（你 SoftAP 就配的信道 6，这是现成的例子）；SSID vs BSSID；WPA2-PSK。
- **AP 的常见问题**：掉线、信道干扰、覆盖盲区、认证不掉线（校园网常见 Portal 认证 / 802.1X）。

### 3. 排障命令与思路（笔试高频 + 上手就用）
- Windows：`ipconfig /all`、`ping`、`tracert`、`arp -a`、`nslookup`、`netstat -ano`。
- 排障顺序：**物理层（网线/灯）→ 链路层（IP/ARP/VLAN）→ 网络层（网关/路由）→ 应用层（DNS/服务）**，逐层排除。
- 经典案例要会讲：能连 WiFi 但上不了网（先 ping 网关 → 再 ping 8.8.8.8 → 再 nslookup）；IP 冲突；获取到 169.254.x.x = DHCP 失败。

### 4. 把你的项目"翻译"成网络语言（面试杀手锏）
| 你做过的 | 对应网络知识 |
|---|---|
| `wifi_connectTo_AP()` 扫描并连接 AP | 无线关联、SSID 匹配 |
| `netifapi_dhcp_start()` + 等待 bound | DHCP 客户端、租约 |
| SoftAP 配 192.168.63.1/255.255.255.0 | 静态编址、子网划分 |
| `netifapi_dhcps_start()` 发地址 | DHCP 服务器端（多数同学只知道客户端） |
| socket connect + HTTP POST | TCP 三次握手之后的可靠传输、应用层协议 |
| `gethostbyname()` | DNS 域名解析 |
| ngrok 隧道 | 内网穿透 ↔ 校园网 NAT/端口映射 |
| 失败重试、probe 自检 | 故障检修思路 |
