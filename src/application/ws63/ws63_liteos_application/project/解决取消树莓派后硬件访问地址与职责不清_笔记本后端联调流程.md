# 解决取消树莓派后硬件访问地址与职责不清：笔记本后端联调流程

> 最新更正：后端最终运行在队友笔记本，不在用户电脑。操作以《解决队友电脑后端地址误限与配置窗口退出_新窗口交接.md》为准；部署队友地址时不用--laptop，新默认入口为configure_backend_and_build_board1.cmd。旧用户电脑IP及拒绝连接记录不代表队友服务器状态。

日期：2026-10-06。当前方案：笔记本承载队友负责的真实API v2后端，用户只负责WS63硬件。本文取代之前操作说明中的树莓派部署步骤。

## 问题、原因和方案

WS63通过HTTP访问一个IPv4地址及端口，不依赖服务器是树莓派还是Windows笔记本。迁移需要更换后端运行位置、板1目标地址和局域网可达性；R200、TCA9555、SLE和LCD接线无需更改。板2只通过SLE接收板1状态，不需要连接Wi-Fi。

现在的数据路径是：R200 → 板1 → Wi-Fi/HTTP → 笔记本API v2；后端返回状态后，板1 → SLE → 板2LCD。手机若参与，也访问同一个笔记本API v2后端。USB连接用于供电、烧录和日志，并不自动替代板1的Wi-Fi数据通道。

用户明确后端源码在队友那里、自己不负责后端。因此不要求用户索取源码或安装后端，也不另写一个冒充真实业务后端的服务。队友应把已有真实服务运行在用户笔记本上，提供可访问的Base URL，并继续负责批次登记、工厂基准及业务算法。

## 已修改的代码与读取依据

- `tools/deployment_setup.py`：增加`--laptop`和可选`--port`。读取本机网卡地址，验证填写的地址属于当前笔记本；预检查真实`/health`与`/device/state`后生成板1配置并构建。密码仍隐藏输入，两个HTTP开关仍由通过检查后的配置开启，离线测试开关关闭。预检查使用直接局域网HTTP，避免系统代理与板1访问路径不同。
- 新增`tools/laptop_network.py`：通过.NET枚举活动网卡、IPv4及网关，避免`Get-NetIPConfiguration`依赖WMI权限；只在唯一物理网卡具备IPv4网关时推荐默认地址，VMware/VPN/虚拟网卡不会被自动推荐。多网卡或热点情况下明确选择实际可达地址。
- 新增`tools/configure_laptop_and_build_board1.cmd`：双击进入笔记本配置流程。旧`configure_pi_and_build_board1.cmd`保留为兼容转发入口，不再要求树莓派。
- `tools/device_control.py`：电脑端查询、选择阶段、Start/Stop/Reset也采用直接HTTP，与板1访问路径一致。
- `application/Kconfig:30`与`:50`：菜单文案改为笔记本局域网后端IPv4与通用HTTP端口；原配置符号及默认行为保留。`clearchain_device_http.c`注释改为通用后端，协议和调度行为无需因服务器换机器而重写。
- 新增`tests/test_laptop_deployment.py`：验证物理网卡推荐、虚拟网卡排除、非法目标拦截、非默认端口、当前本机地址归属、配置/构建/发布串联、check-only不编译、预检查失败即停止和直接HTTP。

读取当前`server.py`发现它是旧`/scan`代理，未配置转发时固定返回APPROVED/GREEN，不是完整API v2服务。`D:/ws/server.py`是保存的HTML页面；`D:/ws/server_files/`是网页静态资源。工作区导航AGENTS.md及逐文件索引也确认这些区别，不把这些文件作为本轮真实后端启动入口。

API规范沿用`ClearChain_API_Contract.pdf`，无需队友重新定义一份硬件接口。既有Stop/armed、重复RSSI、DONE、CP、SLE协议v4和LCD反相OFF修复保留。

后端运行方式参考[Flask官方Windows/Waitress部署说明](https://flask.palletsprojects.com/en/stable/deploying/waitress/)：Windows可直接运行，服务需要面向外部网卡监听；监听地址0.0.0.0不是板1访问地址。后端状态存内存，应按契约使用一个后端进程，并由队友处理并发状态一致性。

防火墙配置依据[Microsoft New-NetFirewallRule文档](https://learn.microsoft.com/en-us/powershell/module/netsecurity/new-netfirewallrule?view=windowsserver2025-ps)。本轮只读取网络信息，没有修改电脑防火墙、热点、网络配置或安装后台服务。

## 新的操作流程：用户只做硬件侧

1. 笔记本、板1和参与联调的手机使用能相互访问的网络。板1使用兼容的Wi-Fi，通常选2.4GHz网络。板2不需要Wi-Fi。若现有校园/访客网络存在客户端隔离，先让队友或网络负责人核对；也可换已具备的路由器/手机热点测试，不要求购买树莓派。
2. 请队友把真实API v2后端运行在这台笔记本上，监听所有网卡，例如0.0.0.0:5000，并处理该端口的局域网入站访问。请队友提供实际端口和完整Base URL，不提供localhost地址代替。
3. 先用手机或网络上的另一台设备访问`http://笔记本IPv4:实际端口/health`。应返回API v2健康信息；再核对`/device/state`。只在笔记本自己能打开页面，不证明板1也能访问。成功的`/health`也不等同于全部业务已验收。
4. 双击`tools/configure_laptop_and_build_board1.cmd`。工具显示当前网卡IPv4；确认笔记本实际网络地址，默认端口5000（有不同端口时用下方指令）。按提示确认板1使用的Wi-Fi名称并输入密码，工具检查API v2，自动生成本地配置、编译、签名、校验并输出板1烧录包路径。不要直接烧未配置地址的API模板。
5. 仅把新生成的部署包烧到板1。板2若已经是`BOARDB_V2_LCD_SLE_20261006_d0899e0d`，继续保留；若仍为旧v3，则先烧这个配套v4板2包。等待100%成功后复位，核对Wi-Fi ready、HTTP enabled=1、正确destination，以及SLE发现、ready和LCD状态。
6. 由队友准备真实batch_id及对应实物标签，确认工厂基准。用户按S1～S5或电脑工具启动采集，观察板1EPC/RSSI、后端返回状态、LCD及LED/蜂鸣器的一致性。CP通过手机或电脑选择。Stop后停止上传，Start再开始；S1～S3/S5的IN/OUT按队友设定间隔执行（演示5秒或默认30秒），S4例外。

当前内部SLE协议为v4，部署板1和显示板2必须配套。后端电脑更换本身不改变SLE协议版本，不要求重新烧已经匹配的板2。

## 操作指令

在PowerShell中，工作目录为`D:/ws/fbb/src`。下面的IPv4是本次只读查询的快照，不会硬编码为新的默认服务器地址；5000也只是契约默认端口，应由队友确认。

```powershell
# 只显示当前笔记本网卡IPv4，不修改网络
& 'D:/ws/tools/python/python.exe' application/ws63/ws63_liteos_application/project/tools/laptop_network.py --json

# 只检查已有后端，不编译、不烧录
& 'D:/ws/tools/python/python.exe' application/ws63/ws63_liteos_application/project/tools/deployment_setup.py --laptop --url http://10.231.28.178:5000 --check-only

# 队友服务就绪后：配置Wi-Fi并生成板1包
& 'D:/ws/tools/python/python.exe' application/ws63/ws63_liteos_application/project/tools/deployment_setup.py --laptop --url http://10.231.28.178:5000

# 实际端口不是5000时，例如5001
& 'D:/ws/tools/python/python.exe' application/ws63/ws63_liteos_application/project/tools/deployment_setup.py --laptop --port 5001

# 手机未就绪时，电脑先查询状态
& 'D:/ws/tools/python/python.exe' application/ws63/ws63_liteos_application/project/tools/device_control.py --url http://10.231.28.178:5000
```

本机连接校园WLAN时，本次读取IPv4为`10.231.28.178`；VMware的`192.168.75.1`与`192.168.169.1`属于虚拟网卡，不能仅因其看起来是192.168地址就填入板1。手机热点/Windows热点/网桥若有不同实际地址，由工具显示后选择对应可达地址。

`127.0.0.1`只代表发起请求的设备自身；板1不能用它访问笔记本。`0.0.0.0`用于后端监听，也不能填作板1服务器地址。笔记本IP改变时重新配置并烧板1，板2不用跟着重烧；演示时请队友或路由器管理者尽量保持该IP固定，并保持笔记本运行且不进入休眠。

如果队友需要配置防火墙，可自行在管理员PowerShell中按实际端口执行下面的局域网规则；`Private`仅适用于该测试网络确实为专用网络时，不默认改网络类别或关闭防火墙：

```powershell
New-NetFirewallRule -DisplayName 'ClearChain API LAN TCP 5000' -Direction Inbound -Action Allow -Protocol TCP -LocalPort 5000 -RemoteAddress LocalSubnet -Profile Private
```

本轮没有执行这条系统修改指令，也没有要求用户代替队友安装后端。对于校园网络的不同策略，由队友或网络负责人核对，不能只凭同SSID保证设备互访。

## 验证结果、当前进度与限制

- 新笔记本部署检查通过，既有7组C固件检查及API v2 loopback HTTP检查通过，共9组验证。
- .NET网卡枚举在本机实际运行成功，正确区分物理WLAN及VMware。WMI方式曾返回拒绝访问，因此实现改为不依赖WMI的只读枚举。

- 真实R200、SLE、LCD和按钮此前的基础验收仍有效；新包实板联合运行、真实后端结果及手机同步依然按原验收步骤完成。服务搬到笔记本不会自动替代这些验收。
