# 解决第二颗 TCA9555 九键漏测与离线进度误判

日期：2026-10-06。按用户要求，`D:/table/星闪杯/Our Next Move.docx` 只作参考；与先前 `D:/ws/embedded.docx`、`D:/ws/03_Embedded_Spec_Bilingual.docx` 等已采用规格冲突时，以先前文件为准。本文按本轮实板串口与当前源码分开记录硬件输入、离线链路和业务功能。

## 本轮解决了什么、如何确认

此前卡住的点是把第二颗 `0x21` 的 I²C 应答当成九键验收，且旧接线记录称它未安装。新板1日志有 `TCA9555 probe ok: addr=0x21, input0=0xff, input1=0xff` 和 `Extra keys ready`，更关键的是 18:18～18:19 `Extra key 1` 到 `9` 每个编号各触发两次。结合 `clearchain_key.c` 的映射，确认第二颗 TCA9555 的九路物理输入、轮询与消抖在这次实板测试中正常：1～5 为上/下/左/右/OK，6～9 为 D1～D4。日志中按键实际顺序是 5、4、3、2、1、6、7、8、9；不能误写为顺序按 1～9。`availability=0` 表示软件允许，`1` 表示当前模式不允许；S1 下 D2/D3 为 1 是预期限制，仍已检测到实际按下。

第二个卡点是早先 R200 有声但零标签，未能判断是否有 UART 回复。本轮板1诊断包给出了收发分类：17:48、17:49 两个 S1 窗口各 `tx=34 rx=0`，当时确实未收到有效帧；随后多个窗口 `rx` 恢复，并读到三种 EPC `...078908`、`...078909`、`...078911`。例如 S1 有 `unique=3 samples=13`、另一轮 `unique=3 samples=7`，且 `rejected=0 dropped=0 bad_frames=0 uart_errors=0`。这证明离线 RFID→SLE→LCD 数量链路可工作，同一 EPC 重读使 samples 增长而 unique 不变。早期零回复的物理根因尚无证据，不能说已彻底排除间歇故障。

板2日志接收到了 S1 完整周期 `phase=1`（开始，`tags=0`）、`phase=2`（读卡中，`tags=1/2/3`）、`phase=3`（结束，保留最终数量）。用户这次粘贴的 `seq=1682` 到 `1693` 明确显示一轮 0→1→2→3→最终 3。板2日志的 `samples=0` 是 `clearchain_display_publish_device_state()` 将 `g_state.total_samples` 固定为 0 的当前代码行为，不能拿它否定板1的真实 `samples=7/13`；若产品要在 LCD 显示采样总次数，需另行修改协议/状态字段和显示实现。`percent=0` 与 `cmd=8` 也不代表后端计算进度或判定已运行；这是离线全状态快照。不要把屏幕显示的 `tags` 当成后端业务通过。

## 功能键、方向键现在能测到哪一步

- **实体键输入：已测。** 板1串口九键每键两次 `Extra key N pressed`。这已经超出只测 S1～S5 的范围。
- **模式允许规则：部分已测。** S1 下 D2（View Original）和 D3（View Image）的 `availability=1` 符合限制；D1/D4 与方向键为 0。可在 S4/S5 的扫描窗口结束后再按 D3，预期 `mode=4/5 availability=0`；D2 只有 CP 模式可用，而当前离线流程没有独立 CP 物理键，尚不能验 CP 条件。
- **功能动作：未实现/未验收。** 当前 `clearchain_device_app.c` 业务事件只处理 S1～S5；方向键和 D 键虽可入队并打印，尚不触发 LCD 导航、手机视图或 HTTP 命令。先前嵌入式规格把十字键列为 v1 不使用，D 键 `OPEN_VIEW` 为可选且目标是手机页面；新参考文档提出设备端历史/图像/CP 页面，与先前规格冲突时不能直接作为本轮固件验收标准。CP 实体键及 D4 业务含义也未有确定的先前规格。

## 稳定性、重连与尚缺项

- 板1 17:57:24 最后一轮扫描结束，17:57:40 出现一次 SLE 断开，17:57:44 重新连接；板2日志中确有一次重新启动，随后完成配对、服务/属性发现和 ready，并恢复 `tags=3` 状态。这支持重启后的恢复，但现有日志没有注明操作者是否**主动只复位板2**及准确时刻，不应把断链原因归定为人工复位。
- 板1 17:57:44～18:14:47 约 17 分钟持续输出系统心跳，片段中无新按键、读卡或再次断链，内存空闲值无单调耗尽迹象。这给出板1侧静置观察证据；若严格验收“双板 ready 后连续 10 分钟无按键、无标签、无复位”，还需要两板带同步时间的完整起止日志，并记录标签已移走。
- 仍需：S5 实物扫描与板2对应状态；S4/S5 下 D3 可用性；明确标记的板2单独复位恢复（若本次未按步骤做）；LED 三色与蜂鸣器实物反馈；按目标规模的批量标签读取及重复性。最新多个单卡/两卡/三卡窗口已成功，但此前两轮 `rx=0` 需要在固定供电/接线/标签摆放条件下复测，不能直接宣称长期可靠。
- 后端 API v2 的可达地址/端口、广东现场 Wi-Fi 和后端实际批次/登记/基准仍待队友提供。离线包没有上传，也没有真实 APPROVED/MONITOR/REJECT、IN/OUT、历史或手机同步验收。队友的天津私有局域网地址仅在天津 LAN 内有效，必须提供广东现场网络可达的地址或联网方案。
