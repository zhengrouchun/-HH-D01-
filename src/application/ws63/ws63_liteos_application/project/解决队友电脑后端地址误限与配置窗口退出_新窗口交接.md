# 解决队友电脑后端地址误限与配置窗口退出：新窗口交接

日期：2026-10-06。工作目录：D:/ws/fbb/src。最新明确方案：取消树莓派；真实API v2后端最终运行在队友笔记本，用户只负责WS63双板硬件。后端源码、安装、运行、业务算法、登记和工厂基准由队友负责。

## 1. 本轮问题及原因

用户报告在确认IP/输入Wi-Fi名称或密码时，按z后终端消失。未提供该次错误日志，不能确认z是在哪个提示处输入。

读取旧`tools/configure_laptop_and_build_board1.cmd`发现：它强制传入--laptop，Python因此拒绝不属于用户电脑的IP；脚本无论成功失败都执行pause，然后exit。程序先报错或结束后，如果用户在“按任意键继续”处按z，窗口会关闭。这能解释一种可能的退出路径，但没有该次现场输出，不能记作已经确认的唯一原因。

普通字母z没有Python退出含义。隐藏密码输入看不到字符是正常现象，输入完整的实际密码后按Enter即可；若提交的WPA密码只有一个z，会因长度不足被拒绝。不要为了通过校验随意补字符，必须使用真实网络密码。

最新后端在队友电脑上，继续校验“目标IP必须属于用户电脑”本身是错误流程，已经更正。此前读到的用户电脑IP10.231.28.178及其5000端口拒绝，仅是旧部署方案的检查结果，不代表队友后端的地址或状态。

## 5. 队友后端就绪后怎么操作

只需要队友提供真实完整Base URL（例如http://队友局域网IPv4:5000）、实际端口，并确认API v2运行及设备可访问。板1需要接入能访问队友电脑的Wi-Fi，用户填写该网络SSID/密码。同SSID不一定允许客户端互访，校园/访客隔离或防火墙要由队友/网络负责人确认。手机也访问同一个后端。

1. 先从用户电脑访问队友的/health与/device/state，或运行下面的check-only。地址填写队友电脑，不填用户电脑旧IP、127.0.0.1或0.0.0.0。
2. 双击`tools/configure_backend_and_build_board1.cmd`，填完整后端URL、实际Wi-Fi名称/密码。隐藏密码输入结束按Enter，窗口结束或失败都会保留。若失败，先看窗口和setup_last_run.json，不盲目重新烧录。
3. API v2检查成功后自动开启上传、构建、签名并发布板1包；仅烧最后输出的新板1包。板2若已为上面的v4包，继续保留。
4. 队友准备真实batch_id、登记及工厂基准，用户执行真实读卡并核对串口、LCD和后端返回。手机未就绪可先用device_control.py查询/Start/Stop。IN/OUT间隔按队友设定，演示5秒或默认30秒，S4例外。

下面192.168.1.20是示例，必须替换为队友真实地址：

```powershell
cd D:/ws/fbb/src
& 'D:/ws/tools/python/python.exe' application/ws63/ws63_liteos_application/project/tools/deployment_setup.py --url http://192.168.1.20:5000 --check-only
& 'D:/ws/tools/python/python.exe' application/ws63/ws63_liteos_application/project/tools/deployment_setup.py --url http://192.168.1.20:5000
```

从已打开的PowerShell运行这些命令，Python结束后终端仍保留。部署到队友电脑不使用--laptop。
