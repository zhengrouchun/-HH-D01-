# 解决双板新版接口台架测试与接线缺口：操作说明

本说明对应 2026-10-03 的 `clearchain_device_app.c`（A 板新版设备接口）和 `clearchain_ui.c`（B 板 LVGL）。固件编译与主机测试已完成；以下实物项目尚未由本工作区验证。逻辑 GPIO 编号不是 HH-D01 排针的物理序号，请按实际板卡丝印/原理图找到同名引脚。**A 与 B 不接数据线，靠 SLE 传状态。两块板各自供电，信号所接外设与所属板共地。**

## 接线

### A 板：R200、两片 TCA9555、按键和反馈

- R200：A `GPIO15 / UART1_TX` → R200 `RX`；A `GPIO16 / UART1_RX` ← R200 `TX`；R200 `GND` ↔ A `GND`。R200 供电按**手上具体模块铭牌**提供稳定电源，当前方案预期独立 5 V，先核查 R200 串口 TX 的电平是否为 3.3 V TTL；若为 5 V，必须降至 3.3 V 后再接 A 的 RX。接好天线再给 R200 上电。UART 参数为 115200 8N1。
- 软件 I²C：A `GPIO13` → 两片 TCA9555 的 `SCL`；A `GPIO14` →两片 `SDA`；两片 `VCC` → 3.3 V，`GND` → A GND。SCL、SDA 各有一组到 3.3 V 的 4.7 kΩ 上拉；若模块已自带上拉，不要重复叠加过多。GPIO13 与板载 USER 键可能共用，运行时不要按板载 USER 键。旧笔记中的 `GPIO12→SCL` **不适用于当前固件**。
- TCA9555 #1 地址 `0x20`：`A0/A1/A2` 全接 GND。若模块引出 `RESET`，保持高电平；`INT` 当前轮询方案不接。#1 `P00/P01/P02` 分别接红/绿/黄 LED 阴极，各 LED 阳极经 470 Ω–1 kΩ 限流电阻到 3.3 V（低电平点亮）。#1 `P03` 接 **3.3 V、低电平触发**有源蜂鸣器模块 `IN`；模块 VCC/GND 依其规格连接，不要让 TCA 引脚直接驱动裸蜂鸣器负载。
- #1 `P10/P11/P12/P13/P14` 分别为 S1/S2/S3/S4/S5。每路按键一端接对应 Px，另一端接 GND，每路 Px 用 10 kΩ 上拉到 3.3 V；按下为低电平。S1–S5 在新版固件中发送 `SELECT_MODE`，不在本地决定后端模式。
- TCA9555 #2 地址 `0x21`：`A0` 接 3.3 V，`A1/A2` 接 GND；与 #1 共用同一 I²C 总线。`P00/P01/P02/P03/P04` 分别为上/下/左/右/OK；`P10/P11/P12/P13` 分别为 D1/D2/D3/D4。每个键同样接 GND 加 10 kΩ 上拉到 3.3 V。#2 未接时 S1–S5 仍可用；新版设备接口的方向键和 D 键暂不发送业务命令。

### B 板：ST7796 SPI 横屏

- B `GPIO7 / SPI0_SCK` → LCD `SCK/CLK`；B `GPIO9 / SPI0_MOSI` → LCD `SDA/MOSI/DIN`；B `GPIO8` → LCD `CS`；B `GPIO1` → LCD `DC/RS`；B `GPIO14` → LCD `RST/RESET`；LCD `GND` ↔ B GND。`MISO/SDO`、触摸和 SD 卡引脚当前不接。
- LCD 的逻辑供电与 `BL/LED` 背光按**实际模块规格**接稳定电源。当前驱动没有背光控制 GPIO；若模块要求 3.3 V，可用独立足流 3.3 V 电源，电源地与 B 共地。不要把未确认支持的背光直接接 WS63 GPIO，也不要把两个电源模块的输出并联。
- 固件以 ST7796、SPI0 mode 0、2 MHz、RGB565、`MADCTL=0x28`、横屏 **480×320** 配置。98×55.5 mm 是用户给出的机械尺寸，软件不拿它算像素。`GPIO7/8/9` 在旧引脚笔记中被列为 Flash 相关风险脚位，而厂商 LCD 示例使用 SPI0 复用；目前只证明编译可行，**先在 B 板单独测试断电、复位、冷启动与 LCD 信号接入是否冲突**，不能从代码推断任意 HH-D01 板型都可安全接线。

## 当前三种 A 包与 B 包

- `output/clearchain/board_a/`：旧离线采集 A 包，保留作 R200/TCA/SLE 排障基线。
- `output/clearchain/board_a_api/`：新版 A 包，但上传双开关关闭；可以查本地外设/SLE 初始化，**不会真正调用 `/device/*` 网络接口**。
- `output/clearchain/board_a_api_mock/`：新版 A 联网台架包，上传双开关打开，默认请求 `192.168.4.1:5000`。只在自己控制的模拟服务/测试网络上用。若电脑地址不同，改 `profiles/board_a_api_mock.config` 中的 `CLEARCHAIN_DEVICE_HOST` 并重新构建；A 的 Wi-Fi SSID/口令在 `clearchain_config.h`，需与电脑同网。
- `output/clearchain/board_b/`：B 板 SLE Client + LVGL/ST7796 包。B 与新版 A 的 SLE 协议均为 V3；不要混烧旧 V2 包。每个目录下的 `manifest.json` 有包哈希和 `hardware_verified:false`。

构建：

```powershell
python D:\ws\fbb\src\application\ws63\ws63_liteos_application\project\tools\build_dual.py api_mock
python D:\ws\fbb\src\application\ws63\ws63_liteos_application\project\tools\build_dual.py b
python D:\ws\fbb\src\application\ws63\ws63_liteos_application\project\tests\run_host_tests.py
```

构建脚本按角色保存独立 `.fwpkg`，结束时恢复 SDK 原配置。烧录请用实际 HH-D01 对应的 WS63 烧录工具，分别选对应目录的 `ws63-liteos-app_all.fwpkg` 并确认板号；本工作区未确认烧录线序、COM 号或工具参数，不能写死。先只烧 B 并看 LCD，再烧 A。串口日志应能看到 LCD 初始化、TCA probe、R200 init、Wi-Fi 与 SLE 连接；背光亮本身不能证明 LCD 初始化成功。

## 不依赖真实后端的逐步台架测试

1. 电脑和 A 板进入同一个局域网。电脑在上述默认地址 `192.168.4.1` 时运行：

   ```powershell
   python D:\ws\fbb\src\application\ws63\ws63_liteos_application\project\tests\mock_device_backend.py --host 0.0.0.0 --port 5000 --batch-id BATCH-TEST-001 --expected 3
   ```

   在另一终端 `Invoke-RestMethod http://127.0.0.1:5000/device/state`，应见 `mode=NONE`、`phase=IDLE`、`batch_id=BATCH-TEST-001`。若 PC IP 不是 `192.168.4.1`，改 profile 中 host、重编并重烧 A。Windows 防火墙须允许该测试端口的局域网连接。

2. 启动 B：确认屏幕以 480×320 横向显示，文字不镜像、边缘不越界，冷启动 5 次没有 Flash init 错误。启动 A：确认 #1 TCA `0x20` 探测、R200 UART、Wi-Fi 连上、两板 SLE 连上；B 不应一直显示 link unavailable。#2 TCA `0x21` 若接上应有 extra keys ready 日志。
3. 按 S1。模拟服务日志应有 `POST /device/command` 200；`GET /device/state` 应变成 `mode=S1, phase=READY, batch_id=BATCH-TEST-001`；B 先短暂显示 `S1 FACTORY selected`，随后显示等待/扫描状态。把 1–3 张已知 EPC 标签放到天线前；A 应上传含真实 `chip_uid` 和有符号 `rssi_dbm` 的非空 `readings`。模拟服务收到 `final:true` 后进入 `DONE/APPROVED`，B 显示结果。这个 APPROVED 是**测试夹具预置**，不能作为真后端评分证据。
4. 无标签时按另一个 S 键：应等待读取，不能发空 `readings`，窗口结束可见本地 no-tag 错误。停掉模拟服务，连续三次状态请求失败后 B 应显示 Server offline；重启模拟服务后状态轮询应恢复。再断电/重启 B，检查其重新连接并拿到 A 的最新 SLE 快照。
5. 多标签可靠性独立测：依次放 1、3、5、11 张已知 EPC，目标若为 20 再测 20 张；每组至少 20 轮，记录每轮已知清单、实际唯一 EPC、重复 RSSI 样本、扫描耗时和漏读。编译与模拟服务通过不能证明读齐率。实物验收还要量电源压降、LCD 背光电流、Wi-Fi/SLE 并发及长时间稳定性。

模拟服务的 `batch_id` 是启动参数预设，**只用于自测**。它不定义实体按键在真实后端如何选择批次。当前 A 固件每约 1 秒发送新读数，留一条样本给非空 `final:true`；无标签不发送空 final，超时后不自动重发可能已入库的扫描段。真实后端仍须统一：按键选模式如何确定 batch_id、增量段与空 final 语义、扫描轮次/分段去重、Start/Stop/READY 转换及 S1 工厂会话映射。对接前不能把模拟服务当生产服务。
