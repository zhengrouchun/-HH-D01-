# 解决 R200 有声但窗口零标签且缺少收发诊断：板1诊断包与分离测试流程

日期：2026-10-06。用户提供的 17:12 后双板串口日志显示板1六个完整 S1 窗口均 `final accepted unique=0 samples=0`；用户确认标签在读取范围、R200 有声。板2重新连接、发现服务和 ready 成功，收到的 `tags=0` 与板1一致。

## 问题与已知原因边界

按键已使板1进入 10 秒采集窗口，不能再归因于未按键或窗口未启动。`R200 uart ready` 只证明 UART 初始化；R200 发声不能单独证明 EPC 通知帧经 UART 到达板1。原离线固件仅打印成功解析的 `EPC=`，对收到 `NO_TAG`、未收到有效帧、帧校验错误等情况没有每轮汇总。因此现有日志不能唯一判断是射频/标签、供电/天线、R200 TX→板1 RX、UART 帧，还是协议解析中的哪一处；不据此断言 R200 损坏。此前同一离线配套包的 S3/S4 曾各读到一张标签，说明链路至少有过成功瞬间。

## 本轮处理

仅在 `clearchain_device_app.c` 的离线 bench 分支增加每轮 R200 统计：成功发出的 inventory 命令 `tx`、校验通过的串口帧 `rx`、成功解析的 `epc`、模块明确回复的 `no_tag`、其他被拒帧 `rejected`，以及环形缓冲丢字节、坏帧、UART 错误增量。每轮 S1/S2～S5 结束后打印一条 `[R200 BENCH]`。读卡命令、时长、去重、SLE v4、LCD、HTTP 关闭状态均沿用原离线包；仅更新板1即可。

首次构建因 ccache 试图向工作区外的 `C:/Users/Stu15/AppData/Local/ccache/tmp` 写临时文件而失败；将 `CCACHE_DIR` 与 `CCACHE_TEMPDIR` 指向工作区 `output/clearchain/ccache_diagnostic` 后，SDK 811 步构建、签名和打包成功。`publish_role.py api_bench` 校验 manifest 中各文件 SHA256、角色和离线标记后发布；二进制中核实有 `[R200 BENCH] tx=` 标记；原目标配置 SHA256 在构建前后同为 `a2721343796f200331ce8e2eca7e62667cd9862569c082b494f1426d709f8780`。新包尚未烧录实板，metadata 保持 `hardware_verified=false`。

## 新包实板操作与判读

1. 断电检查 R200 天线已接、5V 稳定、与板1共地；R200 `TTL_TX` 应连板1 `GPIO16/RX`，R200 `TTL_RX` 连板1 `GPIO15/TX`。UART 为 3.3V TTL、115200 8N1；切勿把 5V 接到 GPIO。然后仅将新包烧到板1，确认 BurnTool 100% 且成功，再复位。板2 v4 不重烧。
2. 看到 `OFFLINE BENCH` 与 SLE ready 后，把此前读成功的同一张 UHF 标签放在天线约 20～30 cm 范围，保持位置/方向；按 S1 一次并等完整 10 秒。保存从 `capture begins mode=S1` 到 `final accepted` 和 `[R200 BENCH]` 的板1串口。不要在这轮中按其他阶段键。若仍为 0，只需再做一轮相同条件的对照。
3. `tx>0, rx=0, bad_frames=0`：发出了命令但没有完整有效回帧，先查模块供电/共地、R200 TX→板1 GPIO16、UART电平/波特率；蜂鸣不能代替串口证据。`bad_frames`/`dropped`/`uart_errors` 增加：优先查接线、共地、供电与信号完整性。`rx>0, no_tag≈rx`：串口已有模块回复，但模块报告没识别标签，查天线、兼容标签、位置/方向及射频设置。`rx>0, rejected>0`：保留完整日志，按帧类型/命令和解析提示再定位。`epc>0` 且 `unique>0`：本轮读卡恢复，再进行 1/2/3 张和重复样本测试。

## 稳定性与读卡可靠性分开做

从当前读卡故障出发，先执行上节的一轮单卡 S1 诊断，取得 `[R200 BENCH]`。然后分开做以下三段，每段单独记开始/结束时间，不在一段中混入另一段的操作：

1. 空闲链路稳定性：取走全部标签，等板2 `service discovery complete`、`ready write ... status=0x0` 且 LCD 显示已连接后开始计时。连续 10 分钟不按 S1～S5、不复位、不断电；两路串口一直保存日志，并在开始、中间、结束看 LCD 是否保持已连接。板1代码约每秒发一次 SLE 心跳，板2用最近心跳维持连接新鲜度，但不逐条打印心跳；所以此段没有 `EPC=` 和新 `CLEAR DISPLAY` 行本身正常。重点看无自发 `Disconnected`、重新 `boot.`、`Load access fault`、LCD `Disconnected/Connecting/Stale` 或停止更新。此段不测读卡。
2. 人工复位恢复：10 分钟结束后另记时刻，保持板1运行，只按板2实体 RST 一次。期待板1先打印 `display disconnected`，板2启动后重新扫描、连接、发现服务 `0x2222`/属性 `0x2323`，`ready write ... status=0x0`，LCD 恢复已连接。这个已知人工操作不计入前述自发断连。
3. 读卡可靠性：板2 ready 后，只放此前读成功的同一张标签，位置/方向不变。按板1 S1 一次，手离开按钮，10 秒内不按其他键、不挪标签；看到 `final accepted` 和 `[R200 BENCH]` 后才开始下一轮。重复共三轮，每轮记 EPC/RSSI、unique/samples、板2 tags 和统计行。如果单卡始终为零，先依据统计行排故，暂不测多张。单卡稳定后，先移走其他标签，再分别放两张、三张，各按一次 S1 完整等 10 秒，比较板1 unique 与板2 Tags read。S2～S5 是阶段键，不代表标签张数；它们各为 3 秒窗口，可在数量测试完成后单独测。
