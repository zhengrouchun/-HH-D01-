## 三、后端地址到来前的最小硬件测试

1. 保留现有离线板1和 v4 板2。用前次读成功的同一张 UHF 标签固定距离、方向，按 S1 一次并完整等待 10 秒；重复两到三轮，每轮记录板1 `EPC/RSSI/unique/samples/final accepted` 和板2 `tags`，拍 LCD 实际画面。若仍持续全零，先核对标签是否在读区、R200 5V 供电、共地和天线，不重复大量空窗口或直接重烧。
2. 单张稳定后，分别只放两张、三张，每轮按一次 S1，完整等待；比较板1 `unique` 与 LCD `Tags read`。一张标签在一轮内多次响应时，确认 `samples` 增加、`unique` 保持 1。S2～S5 各做一轮 3 秒窗口用于阶段切换，补上新日志缺少的 S5。扫描中按另一阶段键会取消前一窗口。
3. 两板分别稳定供电，只复位板2一次，保存断开、重新扫描、服务发现、ready 和 LCD 恢复过程；之后两板连续运行约 10 分钟，期间定期启动读卡，记录意外断连、重启、读卡错误、屏幕异常。已有 LED/蜂鸣器若实物接好，可核对启动红绿黄序列及短鸣。20 标签规模仅在实物标签数量足够时另测。

## 四、向队友索取的资料

### 现在就要，用于后续一次配置板1

1. 队友笔记本真实 API v2 的完整 Base URL：`http://可达IPv4:实际端口`，不带 `/health` 路径；请确认 `/health` 报 API v2、`/device/state` 返回完整状态。当前配置工具只接受普通 HTTP、数字 IPv4 和端口，不接受域名、HTTPS 或路径。服务须持续运行并允许板1连接。
2. 跨广东与天津的实际网络访问方式，重点确认广东现场板1所在 Wi-Fi **自身**可到上述 IPv4/端口。天津普通局域网 `192.168.x.x` 通常不可跨省直达；只有用户电脑的 VPN 能访问，不等于板1能访问。若用 VPN，应有板1可用的路由/网关路径。广东现场 SSID/密码由用户自己在配置工具输入，不必向队友发送密码。

### 业务验收前要队友确认

3. 一个真实 `batch_id`、要使用的实物 EPC 清单、后端是否已完成登记和工厂 RSSI/拓扑基准、预期标签数与一组可核对的真实业务结果。现有 `output/clearchain/bench_validation_20261006/backend_registration_handoff.json` 只是已观察 EPC 的交接资料，其中 `registered_batch_id=null`、`factory_session_confirmed=false`；不能当作已经登记。
