## 当前核心接线：板1

### 第一颗TCA9555，7位地址0x20

```text
板1 3V3    → TCA #1 VCC
板1 GND    → TCA #1 GND
板1 GPIO13 → TCA #1 SCL
板1 GPIO14 ↔ TCA #1 SDA
TCA A2/A1/A0 → 全接GND
TCA INT → 不接（目前轮询）
```

用户说明模块带SCL/SDA到VCC的10k上拉，保持其接到3.3V。SDA/SCL不能上拉到R200的5V。按键上拉与I2C上拉是两组不同用途的电阻。

```text
TCA #1 P10 → S1
TCA #1 P11 → S2
TCA #1 P12 → S3
TCA #1 P13 → S4
TCA #1 P14 → S5

每个Pxx ── 按键 ── GND
每个Pxx ── 10kΩ ── 3V3
```

按下为0，松开为1。TCA的P10是端口1位0，不是HH-D01 GPIO10。四脚轻触按键要选按下才导通的两组触点，不能接在本来已经导通的同一组。

```text
3V3 → 独立470Ω～1kΩ电阻 → 红LED阳极；红LED阴极 → P00
3V3 → 独立470Ω～1kΩ电阻 → 绿LED阳极；绿LED阴极 → P01
3V3 → 独立470Ω～1kΩ电阻 → 黄LED阳极；黄LED阴极 → P02
```

软件使用低电平点亮。每个裸LED都要自己的限流电阻，不能三只共用一个或不串电阻。

蜂鸣器控制：TCA #1 P03→有源低电平触发模块I/O，模块GND→板1GND。模块VCC必须按实际额定电压，并确认3.3V控制兼容；目前资料未明确其型号和额定电压，不将它擅自固定成5V。P03只是控制信号，不能直接给裸蜂鸣器供电。型号未确认时先留空，不阻挡其余验收。

### R200

```text
稳定5V电源正极 → R200 VCC
5V电源GND     → R200 GND和板1GND
板1 GPIO15/TX → R200 TTL_RX
板1 GPIO16/RX ← R200 TTL_TX
R200射频接口  → 匹配的3dBi天线
```

交叉接TX/RX，控制信号为3.3V TTL，供电5V不能接到GPIO15/16。当前程序为UART1，115200、8数据位、1停止位、无校验。射频读卡前连接天线，不能把模块商家图片中的USB/TTL/其他接口混为同一端口。

## 当前核心接线：板2

已按用户选购的ST7796无触摸版、35002 SPI转接板和当前代码核对。

```text
LCD VCC        → 稳定3.3V供电
LCD GND        → 3.3V电源GND和板2GND
LCD SCK        → 板2 GPIO7
LCD SDI/MOSI   → 板2 GPIO9
LCD CS         → 板2 GPIO8
LCD DC/RS      → 板2 GPIO1
LCD RESET/RST  → 板2 GPIO14
LCD LED/BL     → 3.3V高电平，背光常亮
LCD SDO/MISO   → 不接
触摸接口、SD卡接口 → 不接
```

LCD模块手册PDF第5页（手册印刷第3页）的接口表明确VCC为+3.3V；LED是背光控制信号，高电平打开，并非要求用GPIO直接给裸背光供电。供电不能直接接5V。

当前源码RESET为GPIO14，GPIO12没有用作RESET；LED固定高电平时不用GPIO12。保持480x320横屏，不需要为了320x480建议强制改接线或转竖屏。

GPIO14在两块独立板上用途不同：板1是I2C SDA，板2是LCD RESET，两者不冲突也不相互连接。

## 电源与两块板之间的连接

调试阶段两块板继续各自通过USB供电，便于保留串口。R200使用已确认的稳定5V；LCD使用已确认的稳定3.3V。

- 板1和它的TCA、R200及R200电源负极必须共地。
- 板2和LCD及LCD电源负极必须共地。
- 两块板通过SLE无线通信，不需要额外接TX/RX、SPI或I2C线。若它们供电独立，不因SLE要求加跨板地线；统一电源时按电源自身公共地连接。
- 外部3.3V供LCD时，不把外部3.3V输出与开发板板载3.3V输出并联；同样不把两块板的3V3输出并联。
- 以后改成统一电源时再核对板子的输入端和USB供电路径，不能依据GPIO表把电源正极接到任意排针。
- 更改接线先断电。面包板分段电源轨不能仅凭颜色假定全长相通，应查实际连通性。

## 预留扩展：第二颗TCA9555（尚未安装）

只有要实际使用方向键、OK或D键时再接入；当前CP由手机选择、D键可选，不要求它作为核心验收前提。

```text
板1 3V3/GND/GPIO13/GPIO14 → 第二颗VCC/GND/SCL/SDA
第二颗A2/A1 → GND
第二颗A0    → 3V3，7位地址0x21
第二颗INT   → 不接

P00/P01/P02/P03/P04 → 上/下/左/右/OK
P10/P11/P12/P13     → D1/D2/D3/D4
```

每个输入仍需10k到3.3V、按键到GND。当前API应用只执行S1..S5动作，第二颗的底层输入映射不等于业务命令已启用；即使后来安装，方向/OK/D键功能仍需按产品需求实现。没有指定独立CP物理键，不能擅自占用D4或OK。

## 操作顺序：现在就能做

1. 断电后按上述清单核对已有线，已经正常显示的LCD不需要全部拆掉重接。尤其检查LCD RESET是板2GPIO14、R200 RX/TX交叉和各自共地。
2. 继续使用已烧录成功的SERVER/API与CLIENT/LCD固件，没有新功能需求不必为了接线核对重复烧录；BurnTool退出/释放串口后开两个日志窗口。调试串口沿用目前能正常读日志的设置；固件debug UART配置115200，常用8N1，和R200物理串口是不同用途。
3. 先启动板1并看到server advertising，再启动板2方便观察日志；这是测试顺序，不是SLE协议限制。检查connected、authentication/pairing status=0、service discovery complete、ready write=0以及CLEAR DISPLAY状态快照。
4. 看到Server offline/Retrying但SLE连接和状态接收正常时，不重新排查配对。后端HTTP开关关闭及真实服务未联调能解释该画面。
5. S1..S5逐个按下、松开，观察Stage key N input P1x changed 1->0、0->1及Stage button N pressed。当前HTTP关闭时SELECT_MODE可能打印HTTP -1，屏幕不切换；这些与按键是否产生输入事件要分开判断。
6. 双板连续运行10分钟，记录是否自行断连、重启、Load access fault或持续异常。随后分别复位板2、板1，核对重新连上并恢复状态。按真正RESET键；本地HH-D01原理图显示另一个板载用户按钮连接GPIO13，GPIO13当前已作I2C SCL，不把用户键当复位键。
