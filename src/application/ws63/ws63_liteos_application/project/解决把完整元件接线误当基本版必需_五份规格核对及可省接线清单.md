# 解决把完整元件接线误当基本版必需：五份规格核对及可省接线清单

日期：2026-10-11。依据用户本轮指定的五份文件，核对上一份完整接线清单里哪些属于基本版必需、哪些是可选扩展。仅整理说明，未拆线、未修改固件、未烧录。

## 结论

上一份说明给的是“手上所有元件怎样接”，不是“基本版每个元件都必须接”。按本轮两份嵌入式规格，基本版保留五个阶段键；十字方向键v1不使用，D键可选。因此可以暂时不接第二颗TCA9555及其九个按键和九条按键上拉支路。OK未被五份文件分配为必需动作，按最小方案也可不接；这是基于功能范围的判断，不是文档逐字写了“OK禁止接”。

第一颗TCA、S1～S5、R200及天线、LCD仍保留。三色灯与蜂鸣器可从新规格的最小读卡/状态显示方案中省下，但旧问答保留灯光反馈，现有软件也有反馈驱动；它们与“明确v1不使用”的方向键不同，建议已经接好的先保留。

## 1. 可暂时不接：第二颗TCA和九键

第二颗为地址0x21，基本版可省去：

- P00→上键、P01→下键、P02→左键、P03→右键。两份嵌入式规格明确写十字键v1不使用。
- P04→OK键。五份文件未规定它在基本版中的必需动作；当前API应用也未消费该事件，最小方案不需要它。
- P10→D1、P11→D2、P12→D3、P13→D4。规格将D键标为可选，用OPEN_VIEW让手机打开页面；当前API应用只处理S1～S5。D4没有被本轮文件定义成独立必需实体键。
- 这九个键各自的“Pxx→按键→GND”和“Pxx→10kΩ→3.3V”支路。
- 不使用第二颗时，它自己的VCC、GND、SCL、SDA和地址设置连接都不需要保留。

**只能移除第二颗的支路，不移除第一颗共用的电源、地、GPIO13 SCL、GPIO14 SDA。** 如果第一颗的总线/供电是经第二颗模块跳接过去的，先把第一颗改为直接连接板1，不能一拔第二颗就让第一颗断线。

此前记录这两颗各带10kΩ总线上拉；移除第二颗后剩第一颗的总线上拉，不等于总线上拉完全消失。按键上拉、I2C总线上拉用途不同，不把第一颗SCL/SDA上拉一起拆掉。

源码`clearchain_key.c`的`clearchain_extra_keys_init`在0x21探测失败时打印`Extra keys unavailable: TCA9555 0x21 probe failed`然后返回；不因第二颗缺席而停掉五个阶段键。这是源码核对结果，拆线后的实板运行仍需验证。

## 2. 不需要另外增加的实体控制键

- CP实体键：两份嵌入式规格均写“待定：物理键还是只用手机”。现有最小方案由手机选择CP即可，不必新增CP按钮，也不把OK/D4擅自改接成CP。
- Start、Stop、业务Reset实体键：API列出了START_SCAN、STOP_SCAN、RESET命令，概念说明的手机控制面板可发Start/Stop；有软件命令不等于必须各安装一个物理按钮。
- 业务RESET与开发板复位不同。开发板本身的复位能力仍用于调试，不能据此改动板载复位电路。

API第7节标题中的“CP location rule (D4)”指CP位置字段规则，不能作为“第二颗TCA的D4键必须连接”的证据；相同地，规则编号D3不代表实体D3键。

## 3. 当前显示方案本来就不接的线

本轮五份文件规定ST7796通过SPI显示状态，不提供物理排针映射。下面的具体省线结论来自此前已核对的当前驱动与35002模块接法：

- LCD SDO/MISO：不接，当前驱动只写屏幕。
- LCD触摸T_CLK/T_CS/T_SDI/T_SDO/T_IRQ：不接，现有为无触摸显示方案。
- LCD SD卡接口：不接，基本版无需SD卡来显示历史/图像；完整内容由手机展示。
- LCD背光GPIO控制线：不接GPIO12，保留LED/BL到稳定3.3V的连接。省的是GPIO控制线，不是背光高电平。
- 两颗TCA的INT：当前轮询，不接。
- R200 CTS/RTS及额外GPIO控制线：当前UART适配只需TX/RX/GND，保留模块既有正常使能配置。
- 两块HH-D01之间的UART/I2C/SPI数据线：不接，当前两板通过SLE无线传状态。
- 手机/后端电脑到WS63的串口数据线：不需要，业务通过Wi-Fi/HTTP；USB调试线可以继续保留。

这些不是从API文件推算出来的引脚，而是“文档功能范围+当前硬件驱动”共同得出的目标方案。

## 4. LED和蜂鸣器：可精简，建议已接好的保留

三份10月3日概念/嵌入式文档把结果展示规定为LCD色块和文字，未将三色实体LED或外接蜂鸣器列为基本验收必需。故若只搭最小读卡、上传和LCD显示闭环，它们可以暂时不接：

- 第一颗P00的红LED支路、P01的绿LED支路、P02的黄LED支路及各自限流电阻。
- 第一颗P03的外接蜂鸣器IN线，以及该模块自己的VCC/GND支路。

但`Answer to you.pdf`第3页第6项旧流程写的是“读EPC→POST /scan→灯光反馈”；当前代码也保留反馈模块。因此不能说五份文件明确要求取消三色灯，或说蜂鸣器已经验收可以删除。建议已有线路正常时保留；只在排线混乱、先搭最小闭环时将它们作为可后接的反馈附件。

用户已确认外接蜂鸣器为3.3V低电平触发三脚模块，保留时接法仍为VCC→板1 3V3、GND→板1 GND、IN→第一颗0x20的P03。省去它不等于拆R200自身的提示音电路。

## 5. 必须保留的基本接线

```text
板1 → 第一颗TCA：3V3、GND、GPIO13→SCL、GPIO14→SDA
第一颗TCA地址：A2/A1/A0全部接GND，地址0x20
第一颗P10/P11/P12/P13/P14 → S1/S2/S3/S4/S5，每键到GND并各有10kΩ到3.3V
板1GPIO15/TXD1 → R200 TTL_RX；GPIO16/RXD1 ← R200 TTL_TX
R200：稳定5V供电、与板1共地、配套天线
板2GPIO7/9/8/1/14 → LCD SCK/MOSI/CS/DC/RESET
LCD：稳定3.3V供电、与板2共地、LED/BL接3.3V
两块开发板各自供电；板1联网访问后端，两板通过SLE无线通信
```

手机能选S1～S5，不等于文档同意取消实体S键：两份嵌入式规格都明确要求保留五键，验收项包含“按实体S1后手机同步”。LCD也不是手机全界面的重复附件，它承担现场模式/扫描/结果状态，因此当前双板目标仍保留板2和LCD。

## 7. 方法、指令与验证结果

流程：只读提取两份PDF正文及三份DOCX段落/表格，交叉比较功能范围与日期/版本；查当前按键代码确认0x21缺席的处理，以及API消费事件范围；对API第2页和旧问答第3页渲染查看，避免将端点表的phone调用者误读成实体按键要求。

使用的工具/指令：

- `Get-Item -LiteralPath ...`：确认五个文件存在；时间戳辅助定位，版本关系以正文为准。
- Python标准库`zipfile`、`xml.etree.ElementTree`：只读DOCX的`word/document.xml`，按正文与表格顺序提取文字。
- 工作区已有PyMuPDF的`get_text()`、`get_pixmap()`：逐页读取两份PDF，渲染并视觉核对相关页。
- `rg -n`：定位`clearchain_extra_keys_init`、`consume_keys`与第二颗地址失败日志。
- `Get-Content -Encoding UTF8`：读取匹配前后源码，确认并非仅凭日志字符串判断。
- `Get-FileHash -Algorithm SHA256`：同步说明归档前核对旧文件，避免覆盖其他修改。

本次解决了“完整14键接线清单被误认为基本版必须安装”的资料范围问题；未改代码，也不把省略第二颗之后的实板稳定性写成已通过。恢复接线时先保留第一颗及其总线上拉，再按基本方案验收五键、真实读卡和LCD。
