# 解决第二颗 TCA9555 仅有地址应答、缺少九键实测证据

日期：2026-10-06。范围：板1的第二颗 TCA9555（7 位 I²C 地址 `0x21`）及当前离线双板联调。本文是测试步骤与证据边界，**不是实板九键已通过的记录**。

## 卡住的问题、原因与目前证据

此前把第二颗扩展器的 `probe ok`、`Extra keys ready` 误当成可以暂缓处理的接入结果，没有逐个按键的串口证据。旧接线记录说第二颗尚未安装；17:12 的板1串口却有 `TCA9555 probe ok: addr=0x21, input0=0xff, input1=0xff` 和 `Extra keys ready: TCA9555 0x21`。这说明当前 I²C 总线上有 `0x21` 设备应答并完成九个输入初读，但不能仅凭此证明九个按钮已接妥、逐个按下可被识别，物理装配情况仍需核对。

源码 `clearchain_tca9555.h/.c` 定义两颗设备的 `0x20/0x21` 地址并打印探测读值；`clearchain_key.c` 将第二颗 P00～P04 映射上、下、左、右、OK，P10～P13 映射 D1～D4。它以 20 ms 周期轮询，低电平为按下，稳定两次后打印 `Extra key N pressed: mode=M availability=A`。`clearchain_device_app.c` 的业务事件消费者目前只处理 S1～S5；第二颗按键日志证明输入链路，不代表 LCD 页面跳转或后端命令已经实现。

## 现在就能做的九键实测

1. 保持配套离线板1与 v4 板2；这项测试不需要 Wi-Fi、后端地址、标签，也不需要重新编译。若已经改烧带 `[R200 BENCH]` 的板1诊断包，也按同样步骤测。确认第二颗确实接在**板1**：与第一颗共用板1 3.3 V、GND、GPIO13/SCL、GPIO14/SDA；A0 接 3.3 V，A1/A2 接 GND，对应 `0x21`。断电后核对接线，不能带电改线。每个按键输入各有 10 kΩ 上拉到 3.3 V，按下接 GND。
2. 打开板1串口，复位板1，保存启动日志。先找 `TCA9555 probe ok: addr=0x21` 与 `Extra keys ready: TCA9555 0x21`；初始 `input0/input1` 通常为 `0xff`，若按键没有按下却为低位，要查接线。等 SLE ready、且当前读卡窗口结束后开始按键测试。
3. 不放标签，暂不按 S1～S5。按下一个第二颗按键约 0.5 秒后松开约 0.5 秒，再按下一键；每键重复两次，以确认松开后能再次触发。依次按上、下、左、右、OK、D1、D2、D3、D4。记录每次与预期 `Extra key N pressed` 是否一致：上=1/P00，下=2/P01，左=3/P02，右=4/P03，OK=5/P04，D1=6/P10，D2=7/P11，D3=8/P12，D4=9/P13。每次应只对应本键，不能出现串键、漏键或持续连发。
4. `availability=0` 是当前模式可用，`1` 是软件标记不可用；S1 模式下 D2、D3 打印 `1` 属预期，仍可据 `Extra key N pressed` 验证物理输入。程序只在按下时打印，不会打印松开；再次按下可触发可作为松开已被识别的间接证据。按导航/D 键时 LCD 不跳页，不应记成按钮故障，也不能记为页面功能已完成。
5. 若没有 `0x21 probe ok`：先核对第二颗是否实际安装、供电、地址脚及共用 I²C。若有探测但某键无日志：重点核对该 Pxx、10 kΩ 上拉、按钮触点和 GND；其余键正常时不要先重烧固件。若用户目前没有第二颗或九个实体键，则记录为“未装/未测”，不要记“通过”。
